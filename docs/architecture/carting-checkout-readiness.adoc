= Carting Checkout Readiness

Carting owns mutable commercial intent. Only an `active` cart is mutable. It must not prepare an empty, expired, checkout-pending, converted, merged, abandoned, or currency-inconsistent cart for an Ordering handoff. `converted` is reserved for successful checkout completion; a guest cart consumed by merge becomes `merged` instead.

== Canonical readiness checks

Before a cart can produce `CartCheckoutHandoff`, the component checks:

* cart status is `active`;
* cart is not expired by `expiresAt`;
* cart has at least one item;
* every item currency matches the cart currency;
* optional availability checker still accepts each requested quantity.

== Responsibility boundary

Carting does not create the final order. Carting creates and persists a handoff payload, then moves the cart to `checkout_pending`. Ordering remains the owner of committed order documents; the cart may become `converted` only after downstream acceptance is confirmed.

== Integration rule

Producer components may provide availability, tax, promotion, or price-estimate services through Symfony service interfaces. Carting consumes those results through explicit DTO contracts, materializes price/promotion/tax facts as `CartAdjustmentEntity` records, preserves optional producer `sourceReference` provenance, and freezes the adjustment projection into the checkout payload. `CartCheckoutHandoffConsumerInterface` is consumed through `CartCheckoutHandoffCompletionService`; successful downstream acceptance records the returned reference and only then moves the cart from `checkout_pending` to `converted`. Preparation retries reuse the already persisted handoff, and completion retries reuse the recorded downstream reference without calling the consumer twice. Carting keeps those contracts minimal and does not absorb Stocking, Payment, Shipping, Pricing, Promoting, Taxating, or Ordering responsibilities.
